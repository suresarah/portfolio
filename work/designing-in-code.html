Designing in code: faster to build, harder to agree.

I designed the console IT partners use to deploy and run AI agents across their clients, then built it as working code with Claude. Some of that code went through engineering review into production.

My role
Senior Product Designer
Status

How I worked

Team practice
Paired with designers and wrote a guide; a few adopted the workflow

How the work moved

Design used to end at a Figma handoff. Here it ended in working code that engineering could review.

The working prototype became the source of truth for how the product behaved. The Miro board was the source of truth for decisions, because not everyone reviewing the work reads code.

AI made producing solutions faster. It also made alignment, convergence, and a shared source of truth more important.

This one isn't public yet.

The work is unreleased, so I share it in a live walkthrough. It covers how designing in working code changed the hand-off with engineering, how we kept one source of truth when everyone could prototype, how running the product exposed a model that needed simplifying, and the trust questions behind the end-user assistant.
