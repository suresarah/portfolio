Designing in code: faster to build, harder to agree.

On 8os, the console IT partners use to run AI agents across their clients, I designed the agent, deployment and client experiences, then built them in working code with Claude. Engineering reviewed the code and took parts into production.

The gap

Static designs showed what the console looked like, not how it behaved.

Interactions, responsive behavior, and multi-step flows got lost in the handoff, so decisions were revisited once building started.

The switch

Make code part of the design process, not the step after it

BeforeFigma handoff. Engineering translates static specs.
What I didBuilt the beta in code with Claude and pushed it to GitHub for review.

In a console this interconnected, I could decide inside the real interface and catch problems earlier, without mocking every state in Figma.

What shipped

Some of my code became the starting point for production.

Engineers brought parts into production, including the deployment and agent experiences (which the team later merged into one workflow).

I handled the detail work in code (layout, interactions, visual consistency), so engineering could focus on integration.

When everyone could prototype

Speed created a new problem: several working prototypes, and no clear current direction.

With the team, I set up one prototype as the source of truth for behavior, and a Miro board of screenshots for decisions, since not everyone reads code. PMs, content designers, and designers commented and split ownership there.

The point wasn't to slow down. It was to keep moving fast without duplicating work.

Sharing the workflow

Nobody had to use my workflow, so I made it easy to pick up.

I paired with designers, ran demos, and wrote a Confluence guide. A few started using parts of it.

The bigger shift: code became another way to explore a design, not just the step after it.

What I learned

AI made producing solutions faster.
It also made alignment and
a shared source of truth more important.

When anyone can build a working prototype in an afternoon, the hard part moves from making things to agreeing on which thing we’re making.
